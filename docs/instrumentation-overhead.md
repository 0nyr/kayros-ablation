# Supplemental instrumentation overhead

We measured the incremental cost of the supplemental bound callbacks, closure census and backend option readback on a quiet grvingt node in OAR job `7012785`. Each backend uses the same binary in both modes. `KAYROS_ABLATION_INSTRUMENTATION=0` disables this supplemental collection while preserving the numerical settings, algorithm, incumbent callbacks, original native logs and final result. The default mode enables collection. The separate [toggle patch](../patches/overhead-0001-toggle-supplemental-instrumentation.patch) is used only for this measurement and does not modify the frozen 300-second development runtimes.

The [driver](../scripts/measure_instrumentation.py) screens C101, R101 and C104 with 100 customers, requiring an uninstrumented native search closure within 5 seconds before admitting a case to the fixed-work comparison. The outer horizon is 10 seconds. C104 reaches the outer deadline in both backends and is excluded from overhead estimation. Each eligible case receives 10 pairs with randomized enabled/disabled order (seed `20261109`), 1 fixed available CPU core and an 8 GiB address-space cap. All external v0.11 route checking happens after solving and contributes no recorded timing.

All 40 eligible pairs retain identical checked costs and the same timeless native search record and route set. Native route-list order can vary without changing a witness. The [analysis replay](../analysis/instrumentation_overhead.py) therefore sorts the outer route list while preserving every route path and attribute. It removes timestamps, console text and supplemental markers when matching work. Complete pricing logs, CG iteration counts, node/cut/column counts and objective information remain part of the comparison. Raw solver records are unchanged.

| Backend | Instance | Matched pairs | Median paired native difference | Median paired native relative difference | Median paired process-launch relative difference |
|---|---|---|---|---|---|
| CPLEX | C101 n100 | 10 | +1.0 ms | +0.10% | +0.10% |
| CPLEX | R101 n100 | 10 | +1.0 ms | +0.20% | +0.78% |
| HiGHS | C101 n100 | 10 | +1.5 ms | +0.04% | +2.33% |
| HiGHS | R101 n100 | 10 | +68.5 ms | +4.25% | +2.46% |

Differences are enabled minus disabled within each pair. Relative differences use the corresponding disabled run as denominator, then take the median over pairs. Consequently, they need not equal the difference between the two marginal medians. The native log has millisecond resolution, so the smallest differences are at its resolution limit. The process-launch result includes imports, loading, preprocessing, native solving and result publication. It excludes external checking.

These measurements concern the combined supplemental instrumentation on 2 instances and 1 node. They do not isolate individual callback or getter costs and do not estimate overhead for the censored C104 cases. The disabled mode still retains the original incumbent callbacks, native logs, final serialization and the small cost of checking the instrumentation flag. We therefore report incremental supplemental overhead rather than the total cost of observability. Effective-option snapshots could be cached by LP/MIP context in a future separately identified implementation, but no such optimization is included in these numbers.

The artifact set `ms56-overhead/outputs/paired-20261109` contains 86 rows (6 eligibility baselines and 80 paired runs), frozen scripts and patches, runtime manifests, native records and checked candidate evidence. `canonical-summary.json` records the input-row digest and analysis-source digests. `canonical-rows.json` preserves the replayed work signatures alongside the original row information. The initial strict-signature summary is retained as history and is superseded by the canonical route-set replay. A subsequent source review corrected the display-counter interpretation: `TableStream` with factor 1.0 permits every root output attempt, rather than applying a wall-clock throttle. The replay in `review-with-cg-iterations/` therefore retains `iteration_count` as well. All 40 pairs still match and every reported overhead statistic is unchanged.
