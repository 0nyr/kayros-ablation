# ms56 phase 1 solver preparation and development probes

This document preserves the phase 1 preparation checkpoint and short correctness probes. Later implementation and measurements supersede its former launch-gate statements. See the [phase 2 results](ms56-phase2-results.md), [current comparison and closure policy](pilot-proof-parameters.md) and [measured instrumentation overhead](instrumentation-overhead.md). The historical raw `proof_unverified` field remains distinct from the qualified solver-reported closure used in the later development analysis.

We prepared isolated Kayros v1.6.1 sources at commit `50eebc57964ac4f6762719ff21033783a31c12da`, applied the recorded patches, and built separate CPLEX and HiGHS wheels on allocated Grid'5000 grvingt nodes. These artifacts support short correctness and instrumentation probes. They do not establish pilot readiness or measured campaign performance.

## Build and source evidence

The build uses GCC 14.2.0, CPython 3.13.12, pybind11 3.1.0, scikit-build-core 1.1.2, CMake 3.31.6 and Guix Boost 1.89.0. The CPLEX build links the installed IBM CPLEX 12.10 static library. The HiGHS build fetches the source release v1.14.0 selected by Kayros's CMake configuration and links it statically. Runtime inventories record the resolved HiGHS commit, source file hashes, installed Python and extension hashes, wheel hashes and checker identity. Build logs preserve compiler diagnostics.

The initial CPLEX configuration failed because Debian's default environment did not expose Boost. Loading the Guix `boost` module supplies its CMake prefix. Both backends subsequently built successfully. The existing warning about `VRPInstance::BestTravelTimeRoute` lacking a return remains unchanged. A source search finds its declaration and definition with no call site, while the Duration bridge calls `BestDurationRoute`.

| Patch | Purpose | Effect on existing solver behavior |
|---|---|---|
| [0001-kayros-bound-events.patch](../patches/0001-kayros-bound-events.patch) | Optional synchronous bound/termination callbacks, exact-pricing aggregate counters and conservative interrupted bounds | Records root bounds only after complete root pricing, records frontier bounds after an uninterrupted branch, and retains the active branch's inherited bound on interrupted branching |
| [0002-cplex-single-thread.patch](../patches/0002-cplex-single-thread.patch) | Explicit CPLEX thread count of 1 after resetting its defaults | Matches HiGHS's existing explicit single-thread setting |

The interrupted-bound change addresses a concrete source-level problem: the previous final `max(z_lb, q.top()->bound)` could discard the lower inherited bound of an active branch whose unprocessed children were absent from the queue. The patch preserves that inherited bound. It does not claim that a restricted-master objective is a valid global bound. Closure callbacks require native `Optimum` status and a finite incumbent. Other termination paths emit `search_terminated`.

The recorded source inventory covers the complete final prepared tree, including the CPLEX-only thread patch. HiGHS compilation excludes the changed CPLEX translation unit, so this later CPLEX-only edit does not change the HiGHS binary. The final installed CPLEX extension is the rebuilt artifact with the explicit thread setting.

## Worker and warm handoff

The [worker](../scripts/kayros_worker.py) implements the 4 Kayros arms with an explicit ILS strategy, `cut_limit=500`, `solution_limit=3000`, stabilization disabled and an 8,000 MiB default memory limit. The launcher supplies a fixed single-core affinity and an address-space limit before imports. The clock starts at process launch, and all loading and preprocessing remain charged. Full Kayros's fixed prefix deadline is measured from process launch, as approved by the author. Backend selection is checked against the compiled extension's reported identity.

ILS callbacks already return customer-only MAMUT routes. The full arm passes those same routes as `initial_routes` to exact search. The native bridge prepends start depot 0, appends end depot `n+1`, reprices each route using its internal evaluator, checks customer coverage, and sets an incumbent only if the surviving routes form a complete feasible partition. Exact incumbent routes are mapped back from the separate end depot to MAMUT and emitted as customer-only sequences. The worker retains the best in-prefix callback witness in its native result. A final heuristic-return witness qualifies only if it is available before the fixed prefix boundary. Later heuristic candidates remain diagnostics and cannot change the exact warm start or the full arm's incumbent trajectory. If ILS returns early, the worker waits until the fixed boundary before starting exact search, including when no witness exists. A proof returned without improved exact routes therefore cannot erase the retained warm-start routes. Unexpected native depot placement or customer IDs produce an integrity event rather than silently repaired routes.

The worker calls the native `_core.solve_ils` with `to_core(loaded, objective_function='Duration')` and `Params(strategy='ils')._to_ils_core()`, matching the public API's native ILS arguments. The conversion only constructs a native instance from loaded data and does not validate a solution. We bypass the public `kayros.solve` wrapper because its `verify=False` parameter controls input checking, while it still calls the external solution checker unconditionally on return. Initial probes that used this wrapper are retained as superseded development records and excluded from performance evidence. An initial full-arm probe also exposed the wrapper's `Solution.duration` field being incorrectly read as `value`. The direct native result provides `value` and resolves that adapter error.

Native solver repricing remains part of solving. External v0.11 route validation runs afterwards through the common harness. Its durations are neither recorded nor reported. The worker verifies the pinned checker installation identity before importing the loader but performs no external route validation during solving.

## Phase 1 checkpoint and subsequent resolutions

1. Phase 1 exposed only aggregate Exact-pricing counters. [Patch 0003](../patches/0003-kayros-node-closure-census.patch) subsequently added a compact per-node CG closure census and diagnostics for restricted-master infeasibility and unbranched fractional nodes. The phase 2 n25/n50 smoke tests returned matching CG-optimum/certified-final-pricing counts with zero unresolved closures. Current comparison follows the [declared computational and numerical conventions](pilot-proof-parameters.md#source-based-closure-audit-and-stricter-proof-record), with these source-level diagnostics retained as annotations rather than categorical pilot blockers.
2. An earlier version of this audit incorrectly stated that the pinned upstream cut threshold was 0. Independent inspection of raw commit `cabc56ad9cdb22bed81a8a31f1671d40152055e6`, `code/src/bcp/bcp.cpp`, confirms `epsilon_bigger(best_violation, 0.1)` in both admission and return. Kayros uses the same comparison against 0.1. No threshold-changing patch was applied. Phase 2 also reads back explicit backend settings under [patch 0004](../patches/0004-kayros-effective-backend-settings.patch).
3. Subsequent waves validate each produced witness under v0.11 and retain native-versus-checked discrepancies. The complete representation audit and scoped numerical results are in the [phase 2 report](ms56-phase2-results.md). Route checking establishes primal feasibility. The comparison reports solver-declared completion under the documented numerical conventions rather than claiming formal real-arithmetic equivalence of native bounds.
4. The [paired instrumentation check](instrumentation-overhead.md) is complete. All 40 eligible enabled/disabled pairs match native work and checked witnesses. Native median supplemental overhead ranges from +0.04% to +4.25% across the measured cases, with the stated resolution and scope limits.
5. The phase 1 forced outer timeout and prefix regressions test event preservation and handoff semantics. They do not cover every native interruption path or demonstrate that every source-level concern is triggered during search. Later diagnostics preserve this distinction. A demonstrated material contradiction remains an issue to resolve, while a source-level suspicion alone does not suppress qualified conventional closure observations.
6. The [12-instance pilot panel](../configs/pilot-selection.json) and [global prefix-selection rule](pilot-proof-parameters.md#approved-global-prefix-selection) are frozen. The rule minimizes restricted mean reported-closure time, then mean primal Λ, then prefix duration, using 3 paired seeds and a common 3,600-second horizon under the current policy. The main campaign still depends on pilot review, selection of the final global fixed prefix, a common horizon and an immutable launch manifest.

## Historical phase 1 probe observations

Initial short probes returned v0.11-valid C101 witnesses at costs 24,709.177157546477 for n25 (both Kayros exact backends), 49,242.92185601275 for n50 (Kayros CPLEX), and 97,901.1136829868 for n100 (Kayros CPLEX). These are correctness observations from 1 repetition, not a performance ranking. The upstream CPLEX 12.10 probes produced the same checked costs for n25 and n50. Its native costs differ from checked values by approximately -3.64e-12 and -7.28e-12, respectively. The upstream IGP versus materialized ATF audit found a maximum sampled knot/midpoint discrepancy of approximately 3.64e-12. These tiny observed differences do not by themselves transfer a native dual bound between arithmetic contracts.

A forced 0.1-second outer timeout returned no candidate and exercised interruption handling. Initial full-arm probes failed on the adapter field mismatch after retaining valid callback witnesses. Initial ILS/full records using the public wrapper are superseded because of its unconditional external solution check. A later standalone timeout exposed a partially published native sidecar. Publication now uses an exclusive temporary file, flush/fsync and an atomic hard link that refuses an existing final path. Interrupted temporary files remain evidence and are not final solver records. The [prefix regression tests](../tests/test_worker_prefix.py) pass on the allocated node. They inject an early native return and check that exact search waits until the fixed boundary, then inject a better late route and check that it cannot replace the in-prefix witness or enter the accepted candidate stream. The corrected full-arm replays complete on both sizes with prefix 15 seconds and horizon 30 seconds. Each preserves 3 valid candidates, emits 12 in-budget events and has no late event or validation failure. The corrected standalone n25 replay reaches the 15-second deadline while retaining 3 valid candidates, with no validation failure. At this phase 1 checkpoint, no claim was admitted by the stricter raw proof-audit field. Later qualified conventional closure observations are reported separately in the phase 2 analysis.
